# 音频改为「TF 卡流式播放」——实现说明与验收方法

> 生效版本：`bit/4_billboard_banner_audio.bit`（2026-10-20 10:06）
> 适用范围：桌面工程 `billboard_prj1-successful`（AC201 + EG4S20BG256）
> 一句话：**音频不再烧进 `.bit`，而是和图片一起放在 TF 卡的容器里，边读边播。**

---

## 一、为什么改

旧方案（`audio_player.v` + `audio_rom.v`）把 4 段共 4×8192 个样本烧进片内 BRAM：

| 旧方案的问题 | 后果 |
|---|---|
| 每段只有 8192 样本 = **171 ms** | 一段"叮"就没了，撑不起 80 秒解说 |
| 换音频必须**重新综合 + 重新烧板** | 改一个字的配音要等 3 分钟综合，演示现场没法调 |
| 占用 4 块 EMB | 本来就只剩 6 块余量（`PHY-9013` 边缘） |

新方案把这些样本搬到 TF 卡，占卡的音频区，播放时用 96 KB/s 的带宽流式取数 ——
SD 卡单扇区上限约 1.67 MB/s，只用掉 **6%**，不影响图像装载。

## 二、数据流（一张图看懂）

```
                ┌──────────────── sd_card_clk (100MHz) ────────────────┐
                │                                                      │
  TF 卡 ──sd_card_top──> sd_arbiter ──A──> ebm_reader ──> SDRAM 帧缓存 ──> HDMI 图像
   ▲                      │  ▲                                          │
   │                      │  └──B──> audio_stream ──> audio_fifo ──┐    │
   └── CMD17/18 ──────────┘        (按格读扇区)         (2048样本) │    │
                                                                   │    │
                        ┌──────── audio_mclk (12.288MHz) ──────────┘    │
                        │                                              │
                        └──> audio_player_stream ──> HDMI 核 (audio + ACR)
```

四个新模块：

| 文件 | 职责 |
|---|---|
| `src/hdl/sd_arbiter.v` | 卡只有一条读通道，把「图像装载」和「音频取数」按扇区边界仲裁 |
| `src/hdl/audio_stream.v` | 按 FIFO 水位（768/1536）决定何时抢总线，按 10 秒一格算扇区号 |
| `src/hdl/audio_fifo.v` | 100MHz 写 / 12.288MHz 读的跨时钟域样本缓冲（2048 样本 ≈ 42 ms） |
| `src/hdl/audio_player_stream.v` | 48 kHz 节拍从 FIFO 取样本，输出与旧播放器完全相同的 24bit 左右声道 |

**关键设计点**（改代码前必看）：

1. **仲裁只在扇区边界换主人**。`sd_card_sec_read_write` 读完一扇区出 1 拍 `end`，
   下一拍就重新采样输入 —— 所以 grant 必须在 `end` 那一拍切，`a_end/b_end` 用 grant 的旧值门控。
2. **B 一旦抢到就补满才还**（`b_req` 撤掉才释放）。若"读一个扇区就还"，A/B 会各占 50% 带宽，
   音频浪费、图像装载时间翻倍。
3. **`c_req` 必须用 `b_rd` 而不是水位信号** `b_req`。扇区读到一半水位跨门槛会让 `c_req` 抖动，这一帧数据就废了。
4. **死锁兜底**：B 既不想占用也不在读（FIFO 满 / 卡失效）时立即放手，避免 A 等一个永不再来的 `end`。

## 三、TF 卡上的音频区（EBM2 容器）

容器头里新增两个字段（旧 EBM1 卡读出 0 → 自动当作"没有音频"，向后兼容）：

| 偏移 | 长度 | 含义 |
|---|---|---|
| `+0x10` | 4 | `audio_sector` —— 音频区**绝对**起始扇区 |
| `+0x14` | 4 | `audio_bytes` —— 音频区字节数 |

当前素材：

```
audio_sector = 1091778   (= CONTAINER_LBA 1048576 + 43202)
audio_bytes  = 7679984   → 3 839 992 个 16bit 样本 @48kHz = 80.000 秒
一格 = 10 秒 = 960000 字节 = 1875 个扇区（正好整除，不跨格）
8 张图 → 8 格（第 8 格正好用完 80 秒）
```

换图时 `play_scheduler` 给出 `audio_cell`（0~7），顶层取 `audio_cell_tgl` 的边沿得到 1 拍
`jump` 脉冲送给 `audio_stream`，它把读指针直接搬到该格起点 —— 换图即换解说。

## 四、换音频素材怎么做

```bash
# 1) 把新的 wav 放到 assets/audio/voice80.wav（任意采样率/声道，脚本会重采样）
# 2) 重新生成容器
py -3 tools/gen_container.py --img-dir assets/img --audio assets/audio/voice80.wav
# 3) 自检
py -3 tools/check_container.py -c container.bin
# 4) 写卡（UAC 提权）
scripts\4_write_card_auto.bat
```

**不需要重新综合、不需要重新烧板** —— 这是新方案最大的好处。

## 五、验收（上板前先过这三关）

| 关卡 | 命令 / 方法 | 通过判据 |
|---|---|---|
| L1 模块仿真 | `sim/run_iverilog.sh` | `通过 24 项，失败 0 项`；其中 `tb_audio_fifo 15/15`、`tb_sd_arbiter 20/20`、`tb_audio_stream 22/22` |
| L2 综合实现 | `build_audio_syn.log` / `build_audio_phy.log` | 0 ERROR；`#lut 4947/19600`、`#bram 30/64`、`#pll 3/4`、Setup WNS **+7551 ps**、Hold WNS +40 ps、0 FEPS |
| L2' 关键检查 | `billboard_phy.area` | 必须有 **4 条** `lane_lvds_10_1`（u0~u3）—— 少一条就是 TMDS 时钟 lane 被优化掉，必黑屏 |
| L3 板级 | 烧 `bit/4_billboard_banner_audio.bit` | 有图有声；换图时解说不打架、不重复 |

> ⚠️ BitWriter 用 `PROGRAM_FLASH` 只写 Flash、**不重配 FPGA**，烧完必须**断电再上电**，
> 或者改用 `PROGRAM`(SRAM)。否则屏幕上跑的还是上一次的配置。

### 没声音时的排查顺序

1. 图像正常但无声 → 先看是不是烧完没断电（旧配置）；
2. 断电后仍无声 → 用 `py -3 tools/check_container.py -c container.bin` 确认 `audio_bytes > 0`；
3. 容器没问题 → 卡上那份是不是老 EBM1（`magic` 不是 `EBM2` 就一定无声，重写卡即可）；
4. 以上都对 → 检查显示器/电视的音量、以及 HDMI 线是否走的是 HDMI 而不是 DVI 口。
