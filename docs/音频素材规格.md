# 音频素材怎么换成自己的 —— 4 段音效的硬性规格

> ## ⚠️ 本文描述的是【旧方案】：片内 ROM + 4 段 171ms 音效
>
> **2026-10-20 起，音频已改为「TF 卡流式播放」：80 秒语音、每格 10 秒、跟着图片走，
> 换音频只要重写 TF 卡，不用重新综合。**
> 现行方案请看 👉 [`音频-TF卡流式方案-2026-10-20.md`](./音频-TF卡流式方案-2026-10-20.md)
>
> 本文保留的原因：`audio_rom.v` / `audio_player.v` 仍在工程里（`audio_player` 已不被顶层例化），
> `tb_audio_player` 仍在跑回归；如果哪天要退回 ROM 方案，这份规格仍然有效。

> 本文回答一个问题：**我想放自己的四段音频，需要满足什么要求？**
> 全部参数都来自 `tools/gen_audio_rom.py` 与 `src/hdl/audio_rom.v / audio_player.v`，不是估计值。

---

## 一、先想清楚：音频不走 TF 卡

| | 图片 | 音频 |
|---|---|---|
| 存在哪 | TF 卡（`container.bin`） | **FPGA 片内 BRAM**（烧进 `.bit`） |
| 换素材后要做什么 | 只要**重写 TF 卡** | **必须重新综合 + 重新烧板** |
| 数量 | 最多 8 张 | **固定 4 段** |
| 从哪出 | 显示器画面 | **HDMI 口**（显示器的喇叭，板上没有喇叭/耳机口） |

换句话说：**音频不是在"播文件"，而是提前烧进 FPGA 的一段 PCM 采样。**
花 30 秒记住这一条，后面就都不会错。

---

## 二、硬性规格（6 条，缺一不可）

| # | 项目 | 要求 | 为什么 |
|---|---|---|---|
| 1 | **格式** | `.wav`，**16bit PCM** | 脚本 `read_wav_mono()` 里 `if width != 2: raise`，24bit/32bit/mp3 直接报错退出 |
| 2 | **声道** | 单声道或立体声都行 | 立体声自动**取左右平均**混成单声道 |
| 3 | **采样率** | **不限**（44100 / 48000 / 22050…） | 脚本用线性插值自动重采样到 48kHz |
| 4 | **时长** | **≤ 171 ms**，超过**只取前 171ms** | 每段固定 8192 样本 ÷ 48000 = **0.1707 秒** |
| 5 | **数量** | **正好 4 个**（不足自动用内置音效补，超了只用前 4 个） | ROM 固定 4 段，段号写在 `audio_player` 参数里 |
| 6 | **音量** | 峰值**别贴满**，留 20~30% 余量 | 内部要量化成 8bit，贴满会削顶失真 |

> **171 ms 是死线。** 这个 ROM 是给"提示音"用的，不是放歌、不是放人声播报。
> 想做长音频/背景音乐，得改成从 TF 卡流式读取 —— 当前工程没做，属于扩展方向。

---

## 三、★ 为什么只有 171 ms（答辩可以讲）

EG4S20BG256 只有 **64 块 9Kb 块 RAM（EMB）**，而整个工程要用掉 58 块（90.6%）。

- 如果音频存 **16bit**：32768 样本 × 16bit ≈ 60 块 → **全工程超限，TD 报 `PHY-9013`**；
- 改成 **8bit**：约 29 块 → 刚好塞得下。

所以 `audio_rom.v` 里存的是 **8bit 有符号（-128…127）**，读出时符号扩展到 16bit，
`audio_player` 再左移 8 位送 24bit 给 HDMI 核 —— **量化精度 8bit，理论信噪比约 48dB**。

听感上：提示音、蜂鸣、短提示完全够用；人声、音乐会有明显"底噪感"。

## 四、4 段音效和图片怎么对应

`play_scheduler.v` 第 352 行：

```verilog
audio_seg <= {2'b00, want_id[1:0]};   // 段号 = 当前图片 id 的低 2 位
```

**一张图固定配一段音**，按图片顺序循环：

| 图片（按文件名排序） | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 图片 id | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| 播放音效段 | **段0** | **段1** | **段2** | **段3** | 段0 | 段1 | 段2 | 段3 |

- 即 **第 1/5 张同音、第 2/6 张同音、第 3/7 张同音、第 4/8 张同音**；
- 应急按键切到第 1 张图（`EMERG_ID = 0`）→ 同时切到**段 0** 的音；
- **换音效不用改代码，调图片文件名顺序就行**。

### 现有 4 段内置音效（不指定 wav 时的默认值）

| 段 | 内容 | 参数 | 听感 |
|---|---|---|---|
| 段 0 | 短提示音 | 1000Hz 正弦，120ms | 单声"嘀" |
| 段 1 | 双声提示 | 1200Hz，90ms + 70ms 间隔 + 90ms | "嘀-嘀" |
| 段 2 | 上升扫频 | 400→2000Hz，180ms | 上扬"呜↑" |
| 段 3 | 柔和铃声 | 880Hz + 2/3 次泛音，指数衰减，260ms | "叮——" |

> 段 3 的 260ms 超过 171ms，所以实际只播了前 171ms 被截断 —— 听感上就是"叮"刚起声就没了。
> 这是已知现象，**内置音效本身就这样**，不是故障。

## 五、怎么替换（两条命令）

### 方式 A：用自己的 wav

```bash
cd /c/FPGA/billboard_prj

# 把你的 wav 放到 assets/audio/ 下
python tools/gen_audio_rom.py -w assets/audio/a.wav assets/audio/b.wav \
                               assets/audio/c.wav assets/audio/d.wav \
                               -o audio_rom.hex
```

- 给了 1~3 个：剩下的自动用内置音效补（脚本会打印 `段N: 用内置音效补齐`）；
- 给了 5 个以上：只用前 4 个并给警告。

### 方式 B：就用内置 4 段

```bash
python tools/gen_audio_rom.py -o audio_rom.hex
```

### 音频不是 16bit 怎么办

用 ffmpeg 一行转（本机若有）：

```bash
ffmpeg -i 你的音频.mp3 -ac 1 -ar 48000 -sample_fmt s16 -t 0.17 assets/audio/a.wav
#            单声道      48kHz      16bit            截到 0.17 秒
```

> `-t 0.17` 提前截短，比让脚本截断更好 —— 你能先听一遍确认"截在这个位置好听"。

## 六、生成之后：五处同步 + 重新综合

`audio_rom.hex` 必须同时存在于 **5 个位置**（TD 按 `.v` 所在目录解析 `$readmemh`）：

```
C:\FPGA\billboard_prj\audio_rom.hex              ← 工程根
C:\FPGA\billboard_prj\src\hdl\audio_rom.hex      ← ★ 综合时真正读这里
C:\FPGA\billboard_prj\src\rom\audio_rom.hex      ← 存档
C:\FPGA\billboard_prj\billboard_Runs\syn_1\      ← 综合运行目录
C:\FPGA\billboard_prj\sim\audio_rom.hex          ← 仿真用
```

> **漏了不会报 ERROR**，只报一条 `CRITICAL-WARNING`，然后 **ROM 静默变全 0 → 上板无声**。
> 这是最容易踩的坑，所以给了下面这个脚本。

### ★ 一键脚本：`scripts\5_audio_to_bit.bat`

按前面五节生成音频后（或把 wav 拖进去），双击这一个脚本就全做完：
生成 hex → 五处同步 → 重综合布线 → 出新 `bit\2_billboard_full.bit`。

直接双击 → 用内置 4 段音效重跑一遍；
把 wav 拖到脚本图标上 → 用你自己的音频。

## 七、换完怎么看对不对

1. **先仿真**（30 秒，不用等综合）：
   ```bash
   cd /c/FPGA/billboard_prj/sim && ./run_iverilog.sh
   ```
   看到末行 `通过 21 项，失败 0 项` 即结构没问题（`tb_audio_player` 里有"换段生效"检查）。

2. **再上板**：BitWriter → `bit\2_billboard_full.bit` → `Program SRAM`。
   - 声音从**显示器/电视的喇叭**出，不是从板上；
   - 显示器音量调到 30% 以上，很多显示器默认静音；
   - 5 秒内应该听到第 1 张图对应的**段 0** 音效，10 秒后换图 → 换段。

3. **没声音按这个顺序查**（都是踩过的坑）：

   | 现象 | 原因 | 处理 |
   |---|---|---|
   | 完全无声，但画面正常 | `audio_rom.hex` 没同步到 `src\hdl\` → ROM 全 0 | 重跑 `5_audio_to_bit.bat` |
   | 换图了但声音不变 | 图没真的换（TF 卡只有 1 张图） | 先解决图片切换（见写卡文档） |
   | 有"沙沙"底噪 | 8bit 量化本身的噪声，正常 | 素材峰值调低一点（改 `AMP`） |
   | 有"啪"的爆音 | 素材首尾不在零点 | 脚本已自动做 512 点淡出；仍爆就把素材首尾自己加淡出 |
   | 显示器完全无声 | 显示器静音 / 音量 0 / 不支持 HDMI 音频 | 换个带喇叭的显示器或电视试 |

---

## 八、一句话总结

> **4 段 × 每段 ≤171ms × 16bit PCM 的 wav，采样率声道随意，段号 = 图片 id 的低 2 位；
> 改完必须五处同步 hex + 重新综合烧板（图片只需重写 TF 卡，两者别搞混）。**
