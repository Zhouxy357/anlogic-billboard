## 0. 先记住这一条

**Verilog 代码不是"双击运行"的。** 只有三种"跑"法：

| 说法 | 真实含义 | 在哪个软件 | 怎么触发 |
|---|---|---|---|
| **综合** | 把 `.v` 翻译成门级电路 | **TD** | 打开工程 → 点 Synthesize |
| **仿真** | 模拟时序，跑 testbench 看 PASS/FAIL | **Git Bash** | `bash run_iverilog.sh [关键字]` |
| **运行** | 真的执行脚本，生成素材 | **Git Bash** | `python tools/xxx.py` |

> ❌ 不是"把代码复制进软件"。TD 是**按路径**读文件的；仿真器是**命令行点名**文件的。

## 2. 单独跑某一个模块

```bash
cd /c/FPGA/billboard_prj/sim
bash run_iverilog.sh key      # 只跑按键消抖
bash run_iverilog.sh spi      # 只跑 SPI 主机
bash run_iverilog.sh sd       # 只跑 SD 卡全链路
```

> 关键字是**模糊匹配**（拿关键字去比 testbench 文件名）。
> 所以 `audio` 会同时命中 `tb_audio_player` 和 `tb_audio_arc`；
> `seg` 会同时命中 `tb_seg_status`、`tb_seg_scan`、`tb_seg_595` 三个 —— 这是有意的。
> **不写关键字 = 全跑 21 项。**

## 4. 在 TD 里"跑"（综合流程）

### 4.1 点哪里（左侧 FPGA Flow 面板）

```
双击 scripts\1_open_project.bat                     ← 开工程
  ↓
左侧 FPGA Flow → 展开 Syn Opt → 双击 Read Design     ← 验证 37 个源文件 + 1 个约束能一起编译
  应出：0 ERROR（看底部 Console 的 Log Tree 标签页最快）
  ↓
双击 Syn Opt 整行  →  双击 Phy Opt 整行  →  双击 BitWriter
```

- **Console 四个标签页**：`Flow Runs`（各步状态 ✓）/ `Active Run Log`（全部日志）/
  `Tcl Console`（敲命令）/ `Log Tree`（**只看 Error+Warning，查问题先看这个**）
- **重跑某步**：右键 `syn_1` → Reset Runs → 再双击该步
- **报告**：左侧展开 `Design Summary` → `Utilization Summary`（RTL/Gate/Physical Report）
  / `Timing Summary`（Timing Report），双击打开

### 4.2 顺带记住的 TD 菜单

| 想干什么 | 点哪里 |
|---|---|
| 打开工程 | Project → Open Project |
| 看某个 .v 代码 | 左侧文件树**双击文件名** |
| 查找 / 替换 | Edit → Find / Replace |
| 抓芯片内部信号 | Tools → Debug Tools → ChipWatcher |
| 看时序报告 | Tools → Timing Analyzer → Timing Report |
| TD 官方手册 | Help → Software User Guide |

## 5. 结果怎么判 —— 什么才算"正确"

**唯一硬标准：最后一行 `失败 0 项`。**

```
  通过 21 项，失败 0 项      ← ✅ 这就是"正确"，可以往下走
```

想核对到每一行，看这三条（全中才算过）：

| 看什么 | ✅ 正确 | ❌ 不正确 |
|---|---|---|
| 汇总行 | `通过 21 项，失败 0 项` | `失败 N 项`（N > 0）|
| 每一项的结论 | 20 行**全 `PASS`** | 有任何 `FAIL` |
| 括号里的计数 | `n/n` 相等（如 `18/18`）| `17/18` = 挂了 1 条 |

```
### RESULT tb_xxx : PASS  (18/18) ###     ← PASS = 这项过了
### FAIL idx=3 ###                        ← 有 FAIL 时，这行指出第几条挂了
```

**中文乱码不算错**（终端编码问题）—— 只看 ASCII 的 `PASS` / `FAIL` / 数字。
想看中文详情：`python check_results.py`，或打开 `sim/ivlogs/xxx.log`（干净 UTF-8）。

> 完整版（正确的输出长什么样、每项通过标志、反面例子、加强自查）→ `docs\仿真操作说明.md` 第 5 节。

## 7. 跑不过怎么办（四级排查，详见手册第 6 节）

| 级别 | 在哪 | 可能是什么问题 | 先做这个 |
|---|---|---|---|
| **L1 逻辑** | Git Bash | 状态机跳错、计数差一、握手丢数 | 用上表关键字**单跑**那一个 tb |
| **L2 综合** | TD | 语法错、模块没加载、时序违例、hex 读不到 | 看 Console：`ERROR` 必查、`CRITICAL-WARNING` 要查 |
| **L3 芯片内** | 开发板 + TD | 仿真全绿但上板不对 | 用 **ChipWatcher**（TD 自带在线逻辑分析仪）抓真实信号 |
| **L4 板级** | 开发板 | 插错口、卡不兼容、线材坏 | 看手册第 13 步清单，逐项对 |

**TD Console 三种行的读法**：

```
ERROR               ← 必须解决，一个都不许留
CRITICAL-WARNING    ← 要查（例：hex not found → ROM 空 → 上板黑屏）
WARNING             ← 一般可忽略（位宽不等、端口未连接之类）
```

**看波形**（ModelSim 图形界面，比打印直观）：

```
cd /c/FPGA/billboard_prj/sim
vlib work
vlog ../src/hdl/key_debounce.v tb_key_debounce.v
vsim -gui -voptargs=+acc tb_key_debounce   # ★ +acc 不能省，否则 add wave 报 No objects found
# 窗口里敲：add wave -r /*   然后 run -all
# 注意 1：若 vsim 报 Error loading design 但 vlog 是 0 Errors，
#         是暂态故障 —— 在窗口里再敲一次 vsim tb_key_debounce 即可
# 注意 2：add wave / run -all 要敲在 ModelSim 窗口下方的 Transcript 里，
#         不是 Git Bash！Git Bash 里敲 run 会误触发安路 TD 的 run.exe
```

**铁律**：改了任何 `.v` 或 `sim/tb_*.v` → ① 重跑 `run_iverilog.sh`（必须全绿）
→ ② 重跑 `build_manual.py` → ③ TD 里 Read Design + Synthesize（ERROR 归零）→ ④ 再上板。
**绝不改完直接烧板子。**
