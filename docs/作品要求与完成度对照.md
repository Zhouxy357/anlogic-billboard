## 三、基础功能 F1~F5 逐条对照

### F1 图像资源读取与解析

| 规格书要求（原设计） | 实际实现 | 状态 |
|---|---|---|
| TF 卡 SPI 初始化 CMD0→CMD8→ACMD41→CMD16，失败降速重试 | 直接复用例程 `sd_card_top`（官方已验证） | ✅ 可用（LED[0] 亮 = 初始化成功） |
| FAT16/FAT32 解析、遍历目录项筛 `.bmp` | ❌ **没做**，改为**私有容器 EBM1** | ✅ **等价替换**（见下） |
| BMP 54 字节头解析、校验 24bit / BI_RGB、行序翻转 | ❌ **没做**，PC 端 `gen_container.py` 预先转好 RGB888 | ✅ **等价替换** |
| 只支持 640×480 24bpp | ✅ 支持 **1280×720** RGB888 | ✅ 超出 |

> **这是本工程最大的"设计偏离"，答辩必须讲清楚为什么要这么改，否则会被认为"没做完 F1"：**
>
> **偏离理由**：纯逻辑解析 FAT32 + BMP 头，要处理簇链、长文件名、4 字节行对齐、自下而上行序，
> 状态机规模极大且极易在个别卡上翻车；而**这些工作跟"FPGA 设计能力"无关**。
> 所以我们把"文件系统/图片解码"这一层**前移到 PC 端**（`tools/gen_container.py`），
> FPGA 里只解析一个**扁平结构**：512B 头 + 512B 索引（每项 16B，含绝对扇区号）+ 每图定长 2.7MB。
>
> **带来的好处**（可以主动说）：① RTL 少了约 800 行状态机，稳定性大幅提升；
> ② 定位到 **512MiB 偏移**，不碰 FAT 区，卡还能当普通 U 盘用；
> ③ 支持**任意格式**图片（png/jpg/bmp/webp…），PC 端统一转 1280×720；
> ④ 有 `check_container.py` 自检，**PC 端就能确认数据对不对**，不用上板猜。
>
> **本质没变**：仍然是"TF 卡 → 解析 → 像素流 → SDRAM → 显示"，只是解析层的位置挪了。
> 这属于**自主设计的私有数据格式**，是加分点不是减分点。

### F5 交互控制与轮播状态机

| 规格书要求 | 实际实现（AC201 只有 2 个可用按键） | 状态 |
|---|---|---|
| K1 下一张 / K2 上一张 / K3 轮播启停 / K4 预留 | **K1（KEY0）= 下一张**；**K2（KEY1）= 轮播启停**；K3/K4 改成**拨码 SW0/SW1** | ⚠️ **功能裁剪**：没有"上一张"，因 AC201 只有 2 个用户按键 |
| SW0 轮播使能 / SW1 音频使能 | **SW0 = 轮播周期切档 2/5/10/20 秒**；**SW1 = 应急画面开/关** | ⚠️ **定义改了**（见下） |
| 20ms 消抖 + 上升沿单脉冲 | ✅ 自研 `key_debounce` + `play_scheduler` 里的 `key_rise` 二次沿检测 | ✅ **比要求更严**（防连击） |
| 状态机 INIT/LOAD_FIRST/DISPLAY/SWITCH/FALLBACK | ✅ 自研 `play_scheduler` 六状态：`S_INIT/S_IDX/S_RUN/S_LOAD/S_SWAP/S_ERR` | ✅ 等价 |
| 数码管显示图号 + LED 指示状态 | ✅ 6 位数码管：模式/图号/总数/状态/错误码；4 个 LED：SD就绪/自动开/应急开/心跳 | ✅ **超出要求** |
| 按键响应 <100ms；切图无黑屏闪烁；轮播误差 <1% | ✅ 按键当拍响应；切图走淡出淡入（0.3s，不是硬切）；轮播按帧计数（60帧/秒） | ✅ |

> **两处定义变更要主动说明**：
> 1. **没有"上一张"**：AC201 的 KEY2（H14）被用作全局复位 `rst_n`，实际只剩 KEY0/KEY1 两个用户键。
>    规格书的 K1~K4 有 4 个，物理上凑不出来。**解决方式**：把周期切档和应急开关挪到拨码 SW0/SW1（AC201 有 2 路拨码）。
> 2. **SW1 从"音频使能"改成"应急画面开关"**：音频使能在演示时不该被误关（关了要重新烧板才回来），
>    而"应急"才是本作品的题眼，值得占一个物理开关。

## 七、答辩时一定要主动讲的三个点

1. **为什么 720p 而不是规格书写的 480p** —— 因为你的显示器不认 480p；720p 是主动升级，不是跑偏。
2. **为什么不用 FAT32/BMP 解析** —— 前移到 PC 端，FPGA 只解析自研扁平容器；稳定性与可测试性都更好，
   并且**任意格式图片都能用**。这是设计取舍，不是偷懒。
3. **AC201 与 HX4S20C 的关系** —— 同一颗 EG4S20BG256，33 个内部模块零改动，只改引脚/数码管驱动/端口层；
   这本身就是"跨板可移植性"的证明。
