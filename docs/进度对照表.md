## ★ 2026-10-12 晚 代码复查：修掉一个"仿真永远绿、上板必死"的致命 bug

用户要求"再检查代码"，逐模块复查后**发现并修复了一个致命 bug**，另外修复了两处隐患、
记录了一个官方遗留坑。全部改动已过 iverilog 全量回归（**当时 6 项 / 48 条断言；2026-10-13 复核 21 项 / 313 条断言全过**）。

### 🔴 致命 bug：容器索引里的扇区号"相对/绝对"不一致（已修）

EBM1 格式规定索引项里的 `pixel_sector` 是**绝对扇区号**（`ebm_reader.v` 文件头、
verilog 端、testbench 三处都按绝对扇区实现），但 PC 端 `tools/gen_container.py`
写进去的却是**相对容器起点的值**（2、5402、10802…）。

后果：上板后 FPGA 会去读 **绝对扇区 2、5402、…**（那是卡上 FAT32 数据区），
读到的全是垃圾 —— 画面必然不正常。而仿真永远发现不了，因为 testbench 自己造容器时
写的是绝对扇区（`CONTAINER_LBA + 2`）。

**修法**：`gen_container.py` 改为 `start_sector = lba + 2 + idx * PIX_SECTORS`，
并新增**自检**（每次生成都校验索引必须是绝对扇区，不符直接报错退出），防止复发。

| # | 必须重做 | 为什么 |
|---|---|---|
| 1 | **重新双击 `scripts\4_write_card.bat` 写卡** | 卡里那份索引还是相对扇区，必须用新 `container.bin` 覆盖 |
| 2 | TD 里重跑综合出新的 `billboard.bit` | 顶层也改了（心跳灯 + 复位加固），见下 |

### 🟡 修掉的两处"会把整板闷死"的隐患（`top_billboard.v`）

| 隐患 | 后果 | 修法 |
|---|---|---|
| 心跳灯挂在 `video_clk` 上且受总复位控制 | 视频 PLL 一有问题，LED[3] 永远不亮 → 被误判成"没烧进去" | 改用 50MHz 输入时钟自由跑、不受复位：**LED[3] 闪 = FPGA 配置成功** |
| 复位死等三个 PLL 全部锁定，且叠了 `~audio_pll_lock` | 任一 PLL 不锁，整板永久复位，LED/数码管全死 | 加 40ms 超时兜底强行放行（`rst_cnt` 扩到 21 位） |

### 🟠 记录（暂不改动）一个官方遗留坑：`O_video_last` 恒为 0

`src/support/video_rgb_to_axis_640x480.v` 里 `S_x_cnt` 比真实像素号滞后 1 拍，
所以 `S_x_cnt == 1279` 永远不成立 → `O_video_last` **从不拉高**。
这是**官方原例程就有的写法**（官方阈值 639，同样滞后一拍），iverilog 实测确认
（喂 2 行 × 1280 像素，last 脉冲 = 0，user 脉冲 = 1 正常）。

**故意不改**：官方另一个参考视频源 `video_source_test.v` 是**每行**产一次 last，
本工程所用 HDMI 核在 last 恒 0 时是否正常无法在无板条件下判定，
贸然改成 `1278` 有打乱核内部行计数的风险。
若将来"配置正常、其它都对但 HDMI 无输出"，这里（改成 `11'd1278`）是第一个该试的地方。
坑点已写在源码注释里。
